这是为你整理的 Playwright **定位与断言辅助工具**详细功能文档。这些按钮位于 Playwright Inspector 的工具栏上，是提高脚本编写效率、确保测试准确性的核心功能。

---

## 🛠️ Playwright 交互式调试工具功能文档

在使用 `npx playwright test --debug` 或执行 `page.pause()` 呼出的调试界面中，这些功能通过“低代码”方式帮助你生成健壮的测试脚本。

### 1. Pick Locator (定位器拾取)
* **核心意义：** 解决“如何定位这个元素”的难题。
* **主要作用：**
    * 点击该按钮后，在浏览器中移动鼠标，Playwright 会实时高亮显示当前元素。
    * 点击页面元素，工具栏会自动生成符合 **最佳实践** 的定位器代码（优先使用 `getByRole`, `getByText`, `getByTestId` 等用户层面的定位方式）。
    * **应用场景：** 当你不确定该用 ID、Class 还是文本来定位某个复杂的下拉菜单或按钮时使用。

### 2. Assert Visibility (可见性断言)
* **核心意义：** 验证元素是否在页面上“显示”。
* **主要作用：**
    * 点击此按钮后选择页面元素，Playwright 会生成类似 `await expect(locator).toBeVisible();` 的代码。
    * **深层逻辑：** 它不仅检查元素是否存在于 HTML 中，还会检查元素的 `width`/`height` 是否大于 0，以及是否被 `display: none` 隐藏。
    * **应用场景：** 检查登录成功后，“欢迎”文案是否如期出现。

### 3. Assert Text (文本断言)
* **核心意义：** 验证元素内部包含的“文字内容”是否正确。
* **主要作用：**
    * 选中元素后，Playwright 会捕获该元素及其子元素的文本，生成 `await expect(locator).toContainText('预期文字');`。
    * **应用场景：** 检查商品列表里某个商品的名字是否正确，或者检查错误提示信息的内容。

### 4. Assert Value (值断言)
* **核心意义：** 专门针对 **表单元素**（Input, TextArea, Select）的输入值进行验证。
* **主要作用：**
    * 不同于 Text（标签间的文字），Value 关注的是 HTML 元素的 `value` 属性。
    * 生成代码示例：`await expect(locator).toHaveValue('输入的内容');`。
    * **应用场景：** 在输入框输入手机号后，验证输入框里最终显示的数字是否正确；或验证下拉框选中的选项值。

### 5. Assert Snapshot (快照断言)
* **核心意义：** 进行“视觉回归测试”或“大批量数据比对”。
* **主要作用：**
    * **视觉快照：** 拍摄当前元素的截图，并与基准图片（Golden Image）进行像素级比对。
    * **DOM/数据快照：** 也可以用于比对整个组件的 HTML 结构。
    * 生成代码示例：`await expect(page).toHaveScreenshot();` 或 `expect(content).toMatchSnapshot();`。
    * **应用场景：** 验证页面 UI 布局有没有走样（如 CSS 污染导致的按钮错位），或者验证一个巨大的表格数据是否每一行都匹配。

---

### 💡 功能对比表

| 功能按钮 | 针对对象 | 生成代码示例 | 核心目的 |
| :--- | :--- | :--- | :--- |
| **Pick Locator** | 所有可见元素 | `page.getByRole(...)` | 找到元素的“地址” |
| **Assert Visibility** | 任何 UI 元素 | `expect(..).toBeVisible()` | 确认东西“看得见” |
| **Assert Text** | 标签内的文字 | `expect(..).toContainText()` | 确认文字“没写错” |
| **Assert Value** | 输入框/表单 | `expect(..).toHaveValue()` | 确认填入的“内容”对不对 |
| **Assert Snapshot** | 页面或组件 | `expect(..).toHaveScreenshot()` | 确认整体“长得没变” |

---

### 使用建议
在调试模式下，你可以先点击 **Record** 录制动作，然后配合使用 **Pick Locator** 来检查元素，最后利用上述的 **Assert** 按钮点击页面，直接在代码编辑区生成断言语句。这种方式生成的代码往往比手写的 XPath 或 CSS 选择器更稳定，更不容易因为前端框架升级而失效。
